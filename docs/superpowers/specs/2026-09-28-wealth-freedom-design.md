# 财富自由公式计算器 — 设计文档

日期：2026-09-28
版本：第 3 版（在第 2 版基础上新增支出明细模式、收入增长、地区消费水平参考）

## 1. 目标

在 `f:\caifu` 下做一个**双击即可运行**的个人财富自由推演小工具：命令行 + 可视化。回答九个问题：

1. 财富自由目标资产（FIRE Number）
2. 当前储蓄率
3. 预计达到财富自由的年龄
4. 不同收益率下的达成时间
5. 敏感度分析（各参数扰动对达成年龄的影响）
6. 退休后资产能否撑到预期寿命
7. 年支出的分项构成与占比
8. 收入逐年增长下达成年龄如何变化
9. 输出表格、折线图、结论摘要

## 2. 口径约定

所有金额以**今天的购买力**（实际口径）展示，用户输入名义参数，程序内部折算。

```text
实际年收益率 r        = (1 + 名义收益率) / (1 + 通胀率) − 1
实际收入增长率 g      = (1 + 名义收入增长率) / (1 + 通胀率) − 1
月利率          r_m   = (1 + r)^(1/12) − 1
自由门槛        T     = 年支出 ÷ 安全提取率
年储蓄₀               = 年收入 − 年支出          # 派生，不作为独立输入
储蓄率                = 年储蓄₀ ÷ 年收入
分项年化金额          = 金额 × 12（按「月」记）或 金额（按「年」记）
```

**积累期**（按月复利、月末储蓄）：

```text
第 t 年（t 从 0 起）年储蓄 = 年储蓄₀ × (1 + g)^t
FV = P·(1+r_m)^N + PMT·((1+r_m)^N − 1)/r_m        # 仅在 g = 0 时成立
月数 N   = ln((T·r_m + PMT) / (P·r_m + PMT)) / ln(1+r_m)   # 仅在 g = 0 时成立
```

**消耗期**（按年复利、按年支取）：

```text
A_{t+1} = A_t·(1 + r) − 年支出
```

### 2.1 显式假设

- 退休后年支出与在职期年支出**同额**（今天的购买力），消耗期资产继续按实际收益率增值。
- **年支出不随收入增长膨胀**（不建模「生活方式膨胀」）。即收入增长只加快积累，不抬高门槛 T。
- 门槛 T 在整个推演期内恒定（今天的购买力口径）。

**双击运行（无命令行参数）→ 逐项问答；带参数运行 → 命令行直通。** 两条路径共享同一套计算层。

### 3.3 命令行参数

沿用第 1、2 版（`--age`、`--annual-income`、`--annual-expense`、`--assets`、`--monthly-save`、`--life-expectancy`、`--return`、`--inflation`、`--withdrawal`、`--years`、`--scenario`、`--no-table`、`--no-chart`、`--no-pause`、`--selftest`），并新增：

| 参数 | 含义 |
|---|---|
| `--income-growth` | 名义年收入增长率 %（默认取 `--inflation` 的值，即实际不涨不减；允许为负即降薪） |
| `--expense-item` | 分项支出，格式 `类目:条目:金额:频率`，可重复；频率取 `月` 或 `年` |

规则：

- 命令行路径下，年储蓄由 `--annual-income − --annual-expense` 派生；若只给 `--monthly-save` 则按年储蓄 = 月储蓄 × 12 处理（此时年收入未知，口径摘要不显示储蓄率）。
- 给出任意 `--expense-item` 即进入明细模式：**年支出 = 全部条目年化金额之和**，此时 `--annual-expense` 可省略；若两者同时给出则报错，避免口径混淆。
- `--city` 只在问答模式出现；命令行下金额是显式给出的，不需要参考值，因此不提供该参数。
- `--years` 无默认值，显式给出时才在结论末尾追加一条「反推所需储蓄」。

| 函数 | 职责 |

| `expense_items_total(items)` | 分项年化金额之和 |

### 4.1 达成年龄的求解口径

| 情形 | 求解方式 | 精度 |
|---|---|---|
| 收入增长率 = 0 | 闭式解 `months_to_target`，并用 `cross_check` 逐月迭代校验 | 小数月 |
| 收入增长率 ≠ 0 | 逐月迭代（月储蓄按年阶梯上调），见下 | 1/12 年 |

迭代口径（与闭式解在 `g = 0` 时结果一致）：

```text
month 从 1 到 MAX_MONTHS：
    year_index = (month − 1) // 12
    月储蓄      = 年储蓄₀ × (1 + g)^year_index ÷ 12
    assets     += assets × r_m + 月储蓄
    若 assets ≥ T → 达成年龄 = 当前年龄 + month ÷ 12
```

`MAX_MONTHS` 内未达标则返回 `None`（无法达标）。

### 4.2 情景与敏感度的口径

`rate_scenarios` 与 `sensitivity` 都只重算**积累期**的达成年龄，不进入消耗期推演。

## 5. 敏感度分析

以基准情形为中心，对每个参数做单侧扰动，输出达成年龄的变化：

| 参数 | 扰动 |
|---|---|
| 名义收益率 | ±1.0 个百分点 |
| 年储蓄 | ±10%，通过等比缩放全部年储蓄实现，年支出保持不变（门槛 T 不变，只反映积累速度的影响） |
| 收入增长率 | ±1.0 个百分点 |
| 通胀率 | +1.0 个百分点 |

输出表格式：

```text
 参数          变化       达成年龄    相对基准
 基准            —         40.2 岁       —
 名义收益率    +1.0%      39.7 岁      -0.5 年
 名义收益率    -1.0%      40.8 岁      +0.6 年
 年储蓄        +10%       39.5 岁      -0.7 年
 年储蓄        -10%       41.0 岁      +0.8 年
 收入增长率    +1.0%      39.9 岁      -0.3 年
 收入增长率    -1.0%      40.5 岁      +0.3 年
 通胀率        +1.0%      41.2 岁      +1.1 年
```

某行若在该扰动下无法达标，达成年龄列显示「无法达标」。

注意「通胀率 +1.0%」一行的影响明显大于其他行（+1.1 年）：通胀上升会同时压低实际收益率**和**实际收入增长率（因为收入增长率默认跟随通胀，单变量扰动时它保持不变），形成双重打击。这是真实存在的耦合风险，敏感度表如实反映。

### 6.1 口径摘要

```text
=== 口径 ===
年龄 30 岁  预期寿命 85 岁
名义 8.0%  通胀 3.0%  →  实际收益率 4.854%
```

### 6.3 结论摘要

```text
=== 结论 ===
• 按实际收益率 4.854% 推算，预计 40.2 岁达成财富自由
• 距离预期寿命 85 岁还有 44.8 年，退休后每年支取 6.0 万
• 推演到 85 岁资产仍有 443.8 万，不会耗尽
• 若通胀率比预期高 1 个百分点，达成时间推迟 1.1 年
```

最后一条自动取敏感度分析中影响最大的不利扰动。若资产在预期寿命前耗尽，改为明确告警：

```text
• 警告：资产将在 78.3 岁耗尽，比预期寿命早 6.7 岁
```

### 6.5 折线图（matplotlib）

- 横轴：年龄（当前年龄 → 预期寿命）
- 纵轴：资产（万元，今天购买力）
- 主曲线：基准情形的完整生命周期（积累期上升 → 退休期下降或继续上升）
- 辅助曲线：情景收益率下的积累期轨迹
- 参考线：财富自由门槛 T（水平虚线）、财富自由年龄（垂直虚线）
- 输出：保存 PNG 到脚本同目录并打印路径，随后弹窗显示

`--no-chart` 时跳过整个绘图步骤。图形环境不可用时只保存 PNG 并提示。

## 7. 边界与错误处理

沿用第 1、2 版全部规则（实际收益率 ≤ 0 且储蓄不足以抵消购买力缩水时报错、`r_m == 0` 退化、已达标返回 0、负数参数拦截、闭式解与逐月迭代交叉校验）。

新增：

| 情形 | 处理 |
|---|---|
| 年支出 > 年收入 | 报错「入不敷出，年储蓄为负，无法积累」 |
| 预期寿命 ≤ 当前年龄 | 报错「预期寿命必须大于当前年龄」 |
| 达到自由的年龄 > 预期寿命 | 不报错，结论中标注「在预期寿命内无法达成」 |
| 当前资产 ≥ 自由门槛 | 达成年龄 = 当前年龄，消耗期直接从当前开始推演 |
| 同时给出 `--expense-item` 与 `--annual-expense` | 报错「不能同时指定分项支出与年支出总额」 |
| `--expense-item` 格式非法 | 报错并给出正确格式示例 |
| 分项支出合计为 0 | 报错「分项支出合计为 0，请至少填写一项」 |
| `--income-growth ≤ -100%` | 报错「收入增长率必须大于 -100%」 |
| 交互模式下明细支出合计为 0 | 回到支出模式选择，提示「明细合计为 0，请至少填写一项或选择简式」 |
| 绘图失败（无 matplotlib / 无图形环境） | 打印提示，其余结果照常输出，不影响退出码 |

## 8. 窗口停留

双击 `.py` 时 Windows 为 `python.exe` 单独新建控制台，`GetConsoleProcessList` 返回的进程数为 1；从 cmd / PowerShell 启动时宿主进程也在同一控制台，返回数 ≥ 2。据此区分双击与命令行。

`run_cli()` 用 `try / except SystemExit / except Exception / finally` 包裹 `main()`，保证成功、参数错误（exit 2）、未预期异常（打印 traceback，exit 1）三条路径都会走到 `pause_before_exit()`。`--no-pause` 可强制关闭。

5. 收入负增长减速：名义增长率 −5% 的达成年龄必须晚于名义增长率 0
6. 增长口径一致性：`reach_age` 的结果必须落在 `build_lifeline` 标记「达成」的那一年内
7. 默认跟随通胀率：`--income-growth` 缺省（= 通胀率）时实际收入增长率必须为 0，且达成年龄必须与第 2 版基准样例（40.2 岁）一致

## 11. 明确不做（YAGNI）

- **不做联网数据采集**：不抓取实时 CPI 或城市消费数据。数据源不稳定、可能需要 API key、随时失效，与「双击即用、离线、确定性」的定位冲突；且 FIRE 模型的精度瓶颈在收益率假设，不在 CPI 数据。
- 不做跨城市搬迁换算（城市乘数只用于生成明细参考值）
- 不做分段收入增长率（单一增长率参数）
- 不做支出随收入膨胀（生活方式膨胀）
- 不做退休后支出比例（退休后与在职期同额）
- 不做多账户、税费、社保、养老金
- 不做蒙特卡洛模拟
- 不做 Web 界面与交互式图表
- 不做配置文件持久化
